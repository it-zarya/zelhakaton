# CLAUDE.md

Инструкции для Claude Code по проекту **«Сотри туман»**: стенд для выставки об архитекторе И. А. Покровском (Зеленоград).
Тонкий роутер: детали — в `docs/` ([[docs/index|index]]). Не раздувать этот файл.

## Что за проект

Веб-сайт на горизонтальном планшете: игра, где посетитель стирает туман со схемы Зеленограда и находит, где и когда строился город; открытые здания дают карточку с фактом и QR. Культурный хакатон **2026-09-26, 11:00–17:00**. Стадия: игра проходится целиком, дизайн Claude Design перенесён (P0).
Стек: Vite + TypeScript без фреймворка, SVG-карта + canvas-туман.

## Как запустить

```bash
npm install
npm run dev        # vite --host: открыть с планшета по http://<IP-ноутбука>:5173
npm run build      # tsc + vite build → dist/
npm run release    # выкатка в прод: сборка → проверка локально → rsync (docs/deploy.md)
npm run map        # пересобрать public/map.svg и src/data/zones.json из OSM
# Адреса: / — игра, /#/maket — мини-игра «Двигаем коробки», /#/o/<id> и /#/r/<id> — QR-страницы
# Админка контента (только npm run dev, только с этого компьютера): http://localhost:5173/admin.html
```

## Всегда-важное

- **Контент (тексты, этапы, объекты, фото) правится в админке `admin.html`** → пишет `src/data/*.json` и `public/photos/`. `tools/content/build_content.py` отключён (перезаписал бы правки).
- `source/` — сырьё от LLM с ошибками. **Никакой факт не идёт на экран без `docs/factcheck.md`.** Нет источника — не пишем.
- Фото на экране — только Commons с атрибуцией или с разрешения правообладателя (PastVu/музей — нельзя без согласия).
- Не генерировать «архивные фото» и портрет Покровского: только реальные фото с подписью источника.
- Всё офлайн: шрифты, фото, скрипты — локально, без CDN.
- Проверка — на планшете пальцем (Pointer Events), не мышью.
- В 13:00 дня хакатона один этап должен проходиться на планшете, иначе режем P1/P2.
- Коммиты — без подписей ассистента (см. глобальный CLAUDE.md).

## Правила ведения документации

- Новое знание → в тематический файл `docs/`, сюда только строка карты.
- Завершил задачу → запись в `docs/history/` (скилл `task-log`).
- Решение с последствиями → ADR в `docs/decisions/`.
- Наступил на грабли → строка в `docs/pitfalls.md`.
- Не знаешь → «Открытые вопросы» в `docs/index.md`, не выдумывай.
